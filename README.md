# youtube_service

Backend-сервис, который позволяет Telegram-ботам быстро и в больших объёмах отдавать видео и аудио с YouTube.
Каждый файл скачивается один раз, хранится в Telegram-канале и дальше выдаётся из кэша.

## Что делает
- Принимает ссылку на YouTube и возвращает доступные форматы видео/аудио и языки
- Скачивает выбранный формат в фоне и отдаёт прогресс
- Возвращает `channel_id` + `post_id` сохранённого файла, чтобы бот мгновенно переслал его
- Повторные запросы того же видео/формата/языка отдаются из кэша, без повторной загрузки

## Стек
Python, Django 5, Django REST Framework, Celery, Redis, PostgreSQL, yt-dlp, Pyrogram, Docker Compose

## Архитектура
```
Telegram-бот ──► REST API (Django/DRF) ──► Celery-воркер (брокер Redis)
                    │      │                  │ yt-dlp (+ прокси) → Telegram-канал (Pyrogram)
                    │      └─► yt_api (сервис метаданных, асинхронные задачи)
                    ▼
                PostgreSQL (состояние загрузок, прогресс, индекс кэша)
```
- **Метаданные** вынесены в отдельный сервис ([yt_api](https://github.com/jacurlive/yt_api)).
- **Загрузки** выполняются Celery-задачами, прогресс пишется в БД; клиент опрашивает `status?task_id=`.
- **Ключ кэша** — `(youtube_key, format_id, language, is_audio)`: unique-ограничение и проверка готовых загрузок перед постановкой в очередь.
- **Хранилище** — Telegram-канал: диск сервера не растёт, файлы выдаются по ссылке на пост.

## API
| Метод | Endpoint | Назначение |
|---|---|---|
| POST | info | получить форматы по ссылке |
| POST | download | запустить (или переиспользовать) загрузку |
| GET | status | состояние задачи и прогресс |
| GET | files / file | список или получение файлов видео из кэша |
